What changed vs. today's shipped screen

whitespace ratiosame interaction model
  • Same leading checkbox glyph and "None apply" control placement as the current app — this is a spacing/typography-only refinement, not a new interaction model, so it isolates one variable against B/C.
  • Gap between sections is now ~4x the gap between rows within a section (48px vs. ~8-14px) — NN/g's finding that whitespace ratio alone can signal grouping without dividers. Today's shipped version has almost no differentiation here, which is a real candidate for why it reads "clumsy."
  • Checkbox aligns to the first line of wrapped labels (already a fixed bug in the real code — kept here since long condition names like "Heart disease (including a prior heart attack…)" need it).
  • Rationale lines (pregnancy, eating disorder) stay full body weight, never dimmed — unchanged, this was already a deliberate choice.

Open question

  • Research finding: iOS has no native checkbox control — every iOS list this pattern resembles (Settings, Mail, Reminders) uses a trailing checkmark instead. This variant is the safe/incremental option; B and C test the more platform-native alternative.

What this tests

platform-nativevariant axis: divider grouping
  • Trailing checkmark, not a leading checkbox square. Apple's HIG has no native iOS checkbox at all — the idiomatic multi-select list (Settings, Mail's mailbox picker, Reminders' list-selection) shows a trailing checkmark SF Symbol on the selected row. This is the single biggest research-backed change from what's shipped today.
  • "None of these apply" is the first row in the section's own list, not a separate control next to the header — this directly implements the HIG-derived pattern of treating "none" as one more mutually-exclusive row rather than a bespoke widget. Tap it and watch every other row in that section clear.
  • Rows separated by a 1px hairline divider (paper at ~12% opacity) rather than the vertical gap alone — the "variant axis" this sketch isolates against C.
  • Section headers keep normal case at the app's heading role (22px semibold) — deliberately not uppercase/tracked. Research flagged that as legacy plain-style-List behavior; today's inset-grouped default doesn't do that.

Accessibility note (not simulated in HTML)

  • Selecting "None" silently clears other rows in that section — a real build needs a VoiceOver announcement on that state change, not just a visual one.
  • Each "None" row's accessibility label should name its section ("None of these Cardiovascular conditions apply"), not a generic string repeated seven times.

What this tests

platform-nativevariant axis: card boundary
  • Identical row/checkmark/None-as-row treatment to B — the only variable here is each section wrapped in an outlined card (1px paper-at-16%-opacity stroke, 12px radius) instead of whitespace/dividers alone.
  • No fill/tint on the card — outline only. This screen is one of the nine locked to flat charcoal decoration (health/consent data); a filled card would be a new, unverified color pairing. An outline reuses the existing paper token at reduced opacity, so no new contrast pair needs checking.
  • This is the strongest chunking option for a long scroll — seven sections stacked — worth checking whether the card boundaries help scannability more than B's dividers, or just add visual noise.

Risk

  • Cards read as more "form-y" / boxed — closer to the "wall of boxes" chip-grid direction this screen already tried and rejected once, just with rows instead of chips inside each box. Worth a hard look at whether that association reappears here.
