<objective>
Build the five screens that open the app: welcome, the explanation-register choice, age, dietary
pattern, and the privacy explainer.

Purpose: these carry three requirements whose promises are made in copy and must be kept in behaviour.
The age screen's helper tells the user we ask "never to sort you into a different app", so it must not
lead anywhere structurally different — it stores the raw age and hands back to the router, which alone
decides whether the 13+ floor is cleared. Per D-14 there is no tier or gate to resolve client-side, only
a boolean the router reads from that raw value. The dietary pattern helper says the choice "only affects
example foods later — never your health screening", so it must be stored on the profile and never reach
gate resolution. The privacy screen says nothing is shared or synced by default, so this phase must in
fact request nothing and sync nothing.

Output: Six registered step views composed from the shared components, with the age validation tested.
</objective>
