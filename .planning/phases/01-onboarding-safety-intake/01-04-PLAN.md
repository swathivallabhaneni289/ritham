<objective>
Model MINOR-01's tiered parental-consent gate and the client-side mirror of D-05's consent state
machine, expressed as a capability query rather than a navigation decision.

Purpose: MINOR-01 and CROSSGEN-05 pull in opposite directions if implemented naively. MINOR-01 needs age
to change what a minor may do; CROSSGEN-05 forbids age from producing a separate app mode or navigation
fork. Resolving this means age must resolve to a *capability set*, never to a screen hierarchy — the
same screens exist for everyone, and the tier only decides which step comes next and which capabilities
are unlocked. Expressing it as `ConsentCapability` makes the no-fork guarantee checkable rather than
aspirational, and gives the data-layer access gate in plan 01-11 a single source of truth so a bug in
one screen's navigation cannot bypass the gate.

Output: Tier resolution, the four-state consent machine, and the capability matrix — all pure, all
tested with no Xcode.
</objective>
