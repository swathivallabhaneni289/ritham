<objective>
Implement the onboarding flow's branching as one pure routing function over a single shared step
vocabulary, and define EXPLAIN-01's register.

Purpose: CROSSGEN-05 forbids any age-based navigation fork — no separate under-18 app mode, no screen
labelled for one age group. MINOR-01 simultaneously requires age to change what happens next. The only
way to satisfy both is for every user to traverse one step enum, with age changing *which case comes
next* and never *which hierarchy they are in*. Making that a pure function rather than scattered
per-view conditionals is what makes the no-fork guarantee testable before any view exists — which is
exactly what 01-VALIDATION.md's `OnboardingFlowStateTests` row asks for.

Note on placement: 01-RESEARCH.md's Pattern 1 shows an `@Observable` flow-state object whose
`step.view(flow:)` returns a SwiftUI View. The View half cannot live in this Foundation-only target. The
split is deliberate — the routing decision and the answers live here where they are testable today, and
the app target's observable wrapper in plan 01-12 delegates to this function rather than reimplementing
it. No branching logic may exist on the app side.

Output: The step vocabulary, the answer aggregate, the routing function, and the register — tested with
no Xcode.
</objective>

  <action>
    Implement `public enum OnboardingRouter` with
    `public static func nextStep(after current: OnboardingStep, answers: OnboardingAnswers) -> OnboardingStep?`,
    returning `nil` only when the flow is finished. This is the single source of truth for branching —
    01-PATTERNS.md's shared rule is that no view computes its own next step.

    Sequence, per MINOR-01 and §1.1:
    - `welcome` → `explanationRegister` → `age`.
    - After `age`, resolve the tier. When it is `.under13`, go to `parentalConsent`. Otherwise go to
      `dietaryPattern` — DIET-01 requires Q0b directly after age, unconditionally, for every user who
      proceeds.
    - From `parentalConsent`, when `consentState.grantsAppAccess` is false, return `parentalConsent`
      again so the flow stays on the halt screen. Per D-06 the under-13 account is fully locked in every
      state before confirmed — no preview and no partial functionality — so no other step is reachable.
      When consent is confirmed, continue to `dietaryPattern`.
    - `dietaryPattern` → `privacyExplainer` → `calibrationIntro` → `calibrationSession` →
      `calibrationComplete`. Calibration is skippable per D-03: when `calibrationOutcome` is `.skipped`,
      route from `calibrationIntro` straight past the session to the step after `calibrationComplete`,
      never blocking.
    - After calibration, branch on the capability gate rather than on the tier directly: when
      `consentGate.allows(.healthScreening)` is false and the tier is `.teen13to17`, go to
      `teenPartialGateNotice` and return `nil` from there, since MINOR-01 lets a teen use tracking and
      Momentum indefinitely without a parent ever approving. When screening is allowed, go to
      `screeningOpeningDisclaimer`.
    - `screeningOpeningDisclaimer` → `gateSection`. After `gateSection`, go to `clearanceInterstitial`
      when any of G1 through G7 is yes, otherwise straight to `conditionChecklist`. §1.2 requires the
      user proceeds to the checklist after either interstitial, so `clearanceInterstitial` →
      `conditionChecklist` unconditionally.
    - `conditionChecklist` → `severityFollowUps` when any category needing follow-ups was selected,
      otherwise `universalFollowUp`. `severityFollowUps` → `scoffFollowUp` when
      `answers.isSCOFFTriggered`, otherwise `universalFollowUp`. Per D-10 the SCOFF step is not shown to
      every user. `scoffFollowUp` → `universalFollowUp` → `screeningComplete` → `home`.

    Route by consulting `ConsentGate.allows` wherever a capability decides the branch, rather than
    switching on `ConsentTier`. That keeps one enforcement point shared with the data layer in plan
    01-11, so a routing change cannot drift from the access check.

    Add `public static func isReachable(_ step: OnboardingStep, answers: OnboardingAnswers) -> Bool` by
    walking from `welcome` — the views use this rather than re-deriving reachability.

    Write `OnboardingFlowStateTests` covering CROSSGEN-05's no-fork guarantee at the routing level:
    - For a representative age in each tier (8, 15, 40, 70), walk the flow from `welcome` to termination
      collecting every visited step, and assert every visited step is a case of `OnboardingStep`. Assert
      the four traversals differ only in which cases appear and their order — never in the type
      traversed. Assert no step is reachable by one age and structurally absent for another; the
      difference is reachability, not vocabulary.
    - Assert an under-13 in `.pending`, `.emailSent`, and `.linkClicked` never advances past
      `parentalConsent`, and reaches `dietaryPattern` once `.confirmed`.
    - Assert a 15-year-old reaches `calibrationIntro`, `dietaryPattern`, `privacyExplainer`, and
      `explanationRegister`, then terminates at `teenPartialGateNotice` without reaching `gateSection`,
      `conditionChecklist`, or `scoffFollowUp`.
    - Assert the same 15-year-old with consent confirmed does reach `gateSection`.
    - Assert an adult is never routed to `parentalConsent` or `teenPartialGateNotice`.
    - Assert `dietaryPattern` immediately follows `age` for every non-under-13 age tested.
    - Assert `scoffFollowUp` is skipped when the eating-disorder item is unselected and visited when it is.
    - Assert a skipped calibration still reaches the step after `calibrationComplete`.
    - Assert `nextStep` is deterministic: identical answers yield identical results across repeated calls.
  </action>
