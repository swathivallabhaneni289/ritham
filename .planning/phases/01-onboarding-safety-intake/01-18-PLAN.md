<objective>
Close the loop on MINOR-01's consent flow by handling the return trip into the app, then verify the whole
phase — automatically where that is meaningful, and by hand where 01-VALIDATION.md establishes that a
test cannot capture the thing being verified.

Purpose: the parent completes their part outside the app, in an email client. Universal Links are what
bring them back into it rather than into Safari. The security property that matters is that arriving via
a link proves nothing: the app must re-read state from the server, because a link is attacker-supplyable
and a locally granted consent would defeat the entire gate.

01-VALIDATION.md names three verifications as genuinely manual — the band motif's reflow at accessibility
sizes, the consent email round trip with its deep-link handoff, and CoreMotion accuracy on a real walk.
Each is manual for a stated reason: rendering correctness at accessibility sizes is not meaningfully
assertable in a unit test, the email round trip cannot be mocked without losing the thing being verified,
and the simulator produces no motion data at all. Those become checkpoints here rather than fabricated
automated gates.

Output: The universal-link handler, the entitlement, a coverage test proving no step was left
unimplemented, and the phase's human verification.
</objective>

    Add an `Associated Domains` entitlement in `Ritham.entitlements` with an `applinks:` entry for the
    consent domain, and reference the entitlements file from `project.yml` so the generated project picks
    it up. The domain must match the one serving the association file exactly — a mismatch causes the link
    to open Safari with no error anywhere, which is the failure mode hardest to diagnose. Read the domain
    from the same configuration value the consent client uses rather than writing it twice.

    Create `UniversalLinkHandler` with a method taking the incoming `URL` and returning a
    `UniversalLinkRoute`, an enum with a case for the consent confirmation paths and a case for anything
    unrecognised. Validate before acting: the scheme must be HTTPS, the host must equal the configured
    consent domain, and the path must be one of the two consent paths. Reject anything else as
    unrecognised rather than attempting to interpret it.

    The security property that governs this file: receiving a link grants nothing. On a recognised
    consent link the handler triggers a fresh `status` read through `ConsentServiceClient` and lets the
    observed state update the local record. It must not parse a token from the URL and treat it as proof,
    must not read a state from a query parameter, and must not set `ConsentState.confirmed` locally under
    any circumstance. A universal link is attacker-supplyable — anyone can craft one and open it on the
    child's device — so the only trustworthy source of consent state is the server. Plan 01-14 already
    removed the means by giving the client no confirm method; record the reasoning here as a header
    comment so it is not reintroduced.

    Wire the handler into `RithamApp.swift` with `.onOpenURL`. Keep the edit additive and leave the model
    container attachment and the ownership comment intact — this plan is the file's third and final owner.

    Handle the case where the app is launched cold by the link as well as resumed, and where the link
    arrives for a device that has no pending consent record — in that case do nothing beyond a status
    refresh, and never create a record from a link.

    Write `UniversalLinkHandlerTests` with a fake client asserting: a well-formed consent URL on the
    configured domain routes to the consent case and triggers exactly one status read; an HTTP URL is
    unrecognised; a URL on a different host is unrecognised even when its path matches; a URL with a
    matching host but an unrelated path is unrecognised; a crafted URL carrying a state or token query
    parameter does not change local state, and the resulting state is whatever the fake server reports;
    when the server reports `linkClicked` the local record does not become `confirmed`; and an
    unrecognised URL performs no network call and no state change.
  </action>

| Boundary | Description |
|----------|-------------|
| incoming URL → app state | A universal link is attacker-supplyable; anyone can craft one and open it on the child's device |
| Apple domain verification → link routing | If verification fails, links silently open Safari instead of the app |
