<objective>
Implement HEALTH-06's red-flag escalation logic and HEALTH-01's branching as a pure, offline,
unit-tested Swift module: the single place in the product where screening answers become condition tags
and clearance gates.

Purpose: this is the safety-critical core of the entire application. Every Phase 2 workout and nutrition
suggestion is gated by what this module returns, and getting it wrong means either silently
under-restricting a user with a red-flag condition or over-blocking someone who should have access.
`docs/health-screening.md` §5 is the single authoritative statement of the logic and lists sixteen
specific escalation triggers plus three governing principles; this plan transcribes them into code with
a test per rule. It runs entirely on-device with no network call, because HEALTH-01 forbids live
AI-generated advice anywhere in this flow and the app must work offline immediately after screening.

Output: `GateResolution.resolve(_:)` — the one function the rest of the product asks "what is this user
cleared for?" — with rule-by-rule test coverage.
</objective>

    `public static func escalate(tags: Set<ConditionTag>, answers: ScreeningAnswers) -> DomainGates`

    applicable tag's base gate, independently per domain. Gates are never averaged, blended, or softened
    because one tag alone might have been milder. Then apply the sixteen numbered triggers from §5 as
    additional escalations that can only raise a gate, never lower it — implement each as a check that
    computes a candidate gate and folds it in with `mostRestrictive`, so the direction is structurally
    one-way.

    than at intake, so express them as
    `public static func weightLossFeatureGate(tags: Set<ConditionTag>, goalBelowHealthyBMIFloor: Bool) -> ClearanceGate`

    goal-setting time; landing it here keeps all escalation logic in one module.
    Rule 16 is not a personalization block but a standing flag, so express it as
    `public static func requiresIndependentAllergenVerification(tags: Set<ConditionTag>) -> Bool`
    returning true for `.severeFoodAllergy`, with a comment noting §5 states this flag has no expiry.

    Add the two always-on prohibitions from §5's closing section as

    toggle can unlock it. Add
    `public static func showsEmergencyLine(for section: ScreeningSection) -> Bool` returning true for the
    gate section and the urgent interstitial unconditionally, since §5 states the emergency line is never
    conditional on an answer combination. Define
    `public enum ScreeningSection: Sendable, CaseIterable` with cases for the sections this phase renders.
