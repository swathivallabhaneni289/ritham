<objective>
Build the pure-Swift lift session domain in `RithamCore`: the set/session value types with stable
per-set identity, the previous-session auto-fill lookup, superset grouping, and the retroactive
merge/split operations.

Purpose: STRENGTH-01 needs a "most recent set for this exercise" lookup; STRENGTH-03 needs
supersets without a separate creation flow; STRENGTH-05 needs merge and split of past sessions,
which is only possible if a set has identity independent of the session that currently holds it —
02-RESEARCH.md names value-typed sets with no independent identity as an anti-pattern for exactly
this reason. Per D-02 this domain is separate from Phase 1's `CalibrationSession` but reads
`CalibrationThreshold` for the shared qualifying bar.

Output: three new `RithamCore/Strength/` source files and three new test suites.
</objective>

  </read_first>
  <behavior>
    - Merging two sessions yields one session whose set count equals the sum of the inputs' set counts, with every original set `id` present exactly once.
    - After a merge, every set's `supersetGroupID` is unchanged from its pre-merge value.
    - After a merge, `orderIndex` values are contiguous from zero with no duplicates, ordered by `completedAt`.
    - Splitting a session at a given set index produces two sessions whose sets partition the original exactly — no set lost, none duplicated, every `id` preserved.
    - Splitting at index zero or at the set count returns `nil` rather than producing an empty session.
    - Merging a session with itself returns `nil` rather than duplicating every set.
  </behavior>
  <action>
    Create `SessionRevision.swift`, Foundation-only, as a `public enum SessionRevision` namespace
    with two pure functions:

    `public static func merge(_ first: LiftSession, _ second: LiftSession) -> LiftSession?` —
    returns `nil` when the two sessions share an `id`. Otherwise returns a new session keeping the
    earlier `startedAt` and the later `endedAt`, whose `sets` are the union of both inputs sorted
    by `completedAt` with `orderIndex` renumbered contiguously from zero. Every set's `id` and
    `supersetGroupID` must pass through untouched — that pass-through is the whole reason
    02-RESEARCH.md insists sets have independent identity, so this must not rebuild sets from
    their field values.

    `public static func split(_ session: LiftSession, atSetIndex index: Int) -> (LiftSession, LiftSession)?` —
    returns `nil` for an index of zero, an index at or beyond the set count, or an empty session.
    Otherwise returns two sessions: the first keeps sets before `index` and the original session
    `id`; the second gets a fresh session `id`, starts at its first set's `completedAt`, and keeps
    sets from `index` onward. Renumber `orderIndex` contiguously within each result, preserving
    every set `id` and `supersetGroupID`.

    Add a doc comment stating the invariant both functions maintain: set identity and superset
    membership are preserved across any revision, so STRENGTH-05's retroactive editing never loses
    or silently rewrites logged work.

    Create `SessionRevisionTests.swift` as a `@Suite` named `SessionRevisionTests` covering every
    behavior above, including an explicit set-identity-partition assertion for split (the union of
    the two results' set `id` values equals the original's, with no overlap).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| retroactive edit → stored training history | Merge and split rewrite already-recorded sessions, so a defect here silently destroys or duplicates a user's logged work |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Tampering | `SessionRevision.merge` / `.split` | high | mitigate | Preserve every `LiftSet.id` across a revision and assert the partition invariant in `SessionRevisionTests` (union equals original, no overlap), so a retroactive edit can never silently lose or duplicate logged work; reject degenerate inputs with `nil` rather than producing an empty session |
| T-02-10 | Tampering | `SupersetGrouping.join` / `.ungroup` | medium | mitigate | Grouping mutates only the group-ID field on existing sets and never recreates a set, tested by an explicit identity-unchanged assertion |
| T-02-11 | Repudiation | `LiftSession.mostRecentSet` auto-fill | low | mitigate | Auto-fill reads only working sets for the exact exercise identifier and returns `nil` rather than a nearest-match, so a pre-filled weight is never attributed to work the user did not do |
| T-02-SC | Tampering | Swift Package Manager dependencies | low | accept | Zero third-party packages added (02-RESEARCH.md Package Legitimacy Audit: none proposed). The legitimacy seam has no SPM support; a future SPM addition needs manual vetting behind a blocking human checkpoint |
</threat_model>
