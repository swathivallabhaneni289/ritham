<objective>
Build the cardio user interface: activity selection, the live tracked session, training history, and
the opt-in route comparison surface.

Purpose: CARDIO-01 needs an activity-type selector, a manual stopwatch path and full training
history; CARDIO-02 needs GPS metrics shown with a visible confidence indicator rather than a
silently varying number; CARDIO-03 needs route comparison to be opt-in with no default public
leaderboard; CROSSGEN-02 needs the auto-detect confirmation prompt that turns a detection into a
session only on the user's say-so.

Planner decision on CARDIO-03's scope, recorded here because `02-CONTEXT.md` left it open and
02-RESEARCH.md Open Question 4 flagged it: this phase implements single-user route comparison only
— a user comparing their own past sessions on a route they have repeated. No cross-user segment
comparison, no leaderboard, no shared segment times. PROJECT.md and ROADMAP.md both state, as a
permanent milestone-independent exclusion, that Ritham will never build a cross-user aggregate
location visualization, and Ritham's own product research names segment-chasing culture as
something it reacted against. Single-user comparison satisfies CARDIO-03's stated requirement
without approaching that line.

Output: four new views, a rewritten cardio registrar, and one new app-target test suite.
</objective>

| stored route data → rendered surfaces | A GPS breadcrumb trail is the most sensitive data this phase stores; any surface that widens its audience is a disclosure boundary |
| detection candidate → logged session | The transition from a sensor guess to a recorded fact must require user intent |
