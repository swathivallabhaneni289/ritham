<objective>
Establish Phase 2's navigation contract and replace the `.home` stub with a working interim hub.

Purpose: D-05 requires a lightweight interim navigation hub so Phase 2's own features are actually
reachable in the running app — not Phase 4's polished three-item CROSSGEN-01 home, just enough real
navigation to use and test what this phase ships. Without it, every Phase 2 feature would be
unreachable outside debug routing until Phase 4. This plan also declares every Phase 2 step and
registers a placeholder for each in Wave 1, so `PhaseCoverageTests`'s "no unregistered step"
assertion stays green at every wave boundary rather than going red for three waves while feature
screens land.

DIET-01 is already implemented (`DietPlanView`, built in a prior session) and needs no
re-implementation. What it does not have is a route: `SettingsView` is currently constructed
nowhere in app code, so the Settings-editable dietary-pattern path REQUIREMENTS.md describes is
unreachable. This plan supplies that route and verifies the requirement end to end.

Output: eight new step cases, five per-area registrar files holding placeholders, one aggregate
registrar, one hub screen, and one app-target test suite.
</objective>
