<objective>
Extend the existing persistence facade with the complete Phase 2 storage surface, in one plan, up
front.

Purpose: cardio sessions, lift sessions, individually addressable lift sets, and three ordinary
user preferences all need to persist locally. `HealthDataStore` and `RithamModelContainer` are
single shared files, so every Phase 2 accessor is added here rather than incrementally by the five
Wave 3 feature plans — that keeps those plans conflict-free and lets them run in parallel.

Scope note for the executor: this plan deliberately adds accessors that have no caller yet. That is
intended. Plans 02-10, 02-11, 02-12, 02-13, 02-14 and 02-15 are their callers, and none of them may
edit these two files.

Output: four new `@Model` record types, their registration in the one existing container, a set of
new `HealthDataStore` methods, and two new app-target test suites.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| domain values → on-device store | Training history and preferences are written to the file-protected SwiftData store Phase 1 established for sensitive data |
| preference data → screening logic | A preference must never become an input to gate resolution; the isolation is the boundary |
