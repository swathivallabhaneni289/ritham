<objective>
Build the strength logging user interface: exercise selection, set entry with auto-fill, the plate
and one-rep-max calculators, and superset building.

Purpose: STRENGTH-01 needs set logging that auto-fills the previous session's weight and reps;
STRENGTH-02 needs a free plate calculator across all five equipment kinds with nearest-loadable
display; STRENGTH-03 needs supersets built by tapping on two consecutive exercises rather than
through a separate creation flow; STRENGTH-04 needs movement patterns auto-assigned and visible.
All four have their domain logic already built and unit-tested in plans 02-02 and 02-03 and their
persistence in plan 02-08 — this plan is the surface over them and adds no new calculation or
storage logic.

Output: three new views, a rewritten strength-logging registrar, and one new app-target test suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user numeric entry → stored training data | Weight, reps and target values are untrusted input that become a persisted record and a loaded barbell |
| in-progress session state → store | A save writes many set records at once; a defect here silently loses or duplicates logged work |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Tampering | `PlateCalculatorView` input handling | medium | mitigate | Render the calculator's no-value return as an invalid-input state with no plate list, never force-unwrapping and never substituting zero, so an out-of-range entry cannot produce a loadable-looking result (ASVS V5) |
| T-02-11 | Repudiation | auto-fill pre-fill | medium | mitigate | Pre-fill comes solely from the store accessor delegating to the unit-tested lookup, which excludes warm-up sets and other exercises; an unlogged exercise pre-fills nothing rather than a plausible default that a user might accept as their own history |
| T-02-10 | Tampering | superset join and ungroup | medium | mitigate | Grouping calls the pure domain functions that mutate only the group-ID field, asserted by a test comparing set identifiers before a join and after an ungroup, so grouping can never invalidate the identity plan 02-15's merge and split depend on |
| T-02-33 | Information Disclosure | one-rep-max presentation | low | mitigate | The estimate is labelled as a general estimate and the file contains no score, level, rating or percentile framing, preserving the product-wide prohibition D-04 established for derived capability figures |
| T-02-SC | Tampering | Swift Package Manager dependencies | low | accept | Zero third-party packages added. The legitimacy seam has no SPM support; a future SPM addition needs manual vetting behind a blocking human checkpoint |
</threat_model>
