Build the pure-Swift strength lookup and calculator domain in `RithamCore`: equipment definitions,
the plate calculator, a one-rep-max estimator, and the movement-pattern lookup table.

STRENGTH-04 needs an auto-assigned, filterable movement pattern per exercise; MONETIZE-01's

estimator must exist for that list to be truthful rather than aspirational.

types and pure functions — no persistence, no UI, no sensor access.
</objective>

    nearest multiple of `defaultIncrementKg` and return an empty plate list. For a `plateLoaded`
    equipment, compute `(target - barWeight) / 2` per side and fill greedily from the largest
    available denomination down, exactly as 02-RESEARCH.md Pattern 4 specifies. Never return an
    achieved weight the caller cannot actually load.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Tampering | `PlateCalculator.nearestLoadable` | medium | mitigate | Reject non-finite, negative and absurdly large targets by returning `nil` (ASVS V5, the control 02-VALIDATION.md assigns to STRENGTH-02); never return an achieved weight that is not physically loadable from the supplied denominations |
| T-02-07 | Tampering | `OneRepMaxCalculator.estimate` | low | mitigate | Restrict to a named 1-12 rep range and positive finite weights, returning `nil` outside it, so no extrapolated figure is presented as a real estimate |
| T-02-08 | Information Disclosure | `OneRepMaxCalculator` output framing | low | mitigate | Header comment and API shape forbid presenting the estimate as a score, grade, level, percentile or rating, preserving D-04's standing rule |
| T-02-SC | Tampering | Swift Package Manager dependencies | low | accept | Zero third-party packages added (02-RESEARCH.md Package Legitimacy Audit: none proposed). The legitimacy seam has no SPM support, so any future SPM addition needs manual vetting behind a blocking human checkpoint |
