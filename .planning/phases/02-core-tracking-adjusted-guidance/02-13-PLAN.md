<objective>
Build the Recommendations surface, the ONBOARD-01 triggered pre-assessment behind it, and the
client that calls the Go workout-plan service.

Purpose: D-01 puts ONBOARD-01's real pre-assessment in this phase rather than deferring it. D-03
makes its entry point a dedicated Recommendations surface the user explicitly opens, matching
ONBOARD-01's "the first time they request recommendations" wording rather than an inferred moment
folded into other guidance. D-04 keeps completion baseline-only: it never appears in training
history and never counts as a logged session. D-06 and D-07 put plan generation behind the Go
service with the smallest data surface that still works.

ROADMAP Phase 2 criterion 8 states the pre-assessment runs through the new session domain rather
than reusing Phase 1's calibration session type, with completion staying baseline-only. That is
what this plan implements: the assessment is measured with this phase's own progress types, its
result is converted into the existing baseline value, and no training-session record is ever
written.

Output: one network client, two views, a rewritten recommendations registrar, and one new
app-target test suite.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → Go API | The first time any Ritham data leaves the device; everything crossing widens the pre-launch privacy-review surface |
| network response → rendered plan | An untrusted response body is decoded and shown as guidance a user will act on |
