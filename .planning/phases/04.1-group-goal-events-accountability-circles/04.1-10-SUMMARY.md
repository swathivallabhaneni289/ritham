## Accomplishments

- `internal/events` package: `Create`/`List`/`Get` for Goal-Events, gated by `MembershipGate` (plan 04.1-08's `RequireMember`, injected, never restated). Activity type is validated against a closed vocabulary mirroring `RithamCore.ActivityType.known` (run/walk/cycle/hike/swim/elliptical) so the client and server never drift apart on what counts as a known activity.
- `RSVPState` is a count and a viewer boolean, nothing else -- reflection-asserted to have exactly those two fields, and proven (via a directly-inserted completion row, since `LogCompletion` doesn't exist in that test file's own scope) to never reference `event_completions` in any way.
- `LogCompletion` is a binary fact with an optional own time: window-bounded (a single-day event with `ends_on == starts_on` still accepts a completion posted any time that day), duplicate-rejected (`(event_id, user_id)` unique constraint mapped to `ErrAlreadyCompleted`), and photo-ownership-verified through an injected `PhotoOwnershipChecker` that fails closed by default. `Completions` selects only `group_visible` rows ordered by `posted_at` ascending -- no `COUNT(`, no join to `event_rsvps`, verified by a test that deliberately runs three completions' own times in the opposite order of their post times.
- The `CompletionVisibility` seam plan 04.1-08 left as a tested no-op is now real: `events.NewCompletionVisibility()` clears `group_visible` on a leaver's completions within the same transaction as their membership deletion, wired into `groupssvc` in `main.go`. Since `internal/groups`' own `membership_test.go` cannot import `internal/events` without an import cycle, the real end-to-end keep/remove behavior is proven from the `events` side instead (`TestCompletion_LeaverDispositionControlsListedVisibility`), while 04.1-08's own spy-based unit tests keep passing unchanged.
- Eight authenticated HTTP routes (`internal/httpapi/events_handler.go`). `CompletionRequest` gets the full `WorkoutPlanRequest`-style treatment: a header comment naming every field and why it exists, reflection-locked field count and JSON tags. `CompletionResponse` uses `omitempty` on every optional field, so a completion logged with an own time and one logged without differ on the wire by exactly the `ownTimeSeconds` key.
- `internal/events/noranking_test.go`: a structural source gate over `internal/events` and `internal/httpapi` (10 files scanned, above the 6-file floor). It fails on any whole-word occurrence of `rank`/`score`/`leaderboard`/`position`/`winner` in non-comment source (word-boundary matched, so `disposition` never false-positives on `position`), and on any SQL `ORDER BY`/aggregate or Go-level `sort.Slice` applied to `own_time_seconds`.

## Decisions Made

- **Exported `groups.DBTX` as a true type alias, verified against the compiler first.** Plan 04.1-08's `CompletionVisibility.HideGroupCompletions(ctx, tx dbtx, ...)` uses `dbtx`, an unexported interface type. I wrote a throwaway probe package declaring a structurally-identical local interface and asserted `var _ groups.CompletionVisibility = (*probe)(nil)` -- it failed to compile ("wrong type for method HideGroupCompletions... have ... myDBTX ... want ... groups.dbtx"), confirming Go's interface satisfaction requires exact parameter-type identity, not just an equivalent method set. `type DBTX = dbtx` (a true alias, not a new type) is the minimal fix: one line, no existing call site touched, and `events.completionVisibility.HideGroupCompletions`'s `tx groups.DBTX` parameter is now literally the same type as `dbtx`.
- **`PhotoOwnershipChecker` fails closed, not open.** `groups.CompletionVisibility`'s no-op default is safe because an unwired seam simply does nothing (a leaver's posts stay visible, the least-surprising outcome pending real wiring). A photo-ownership check's unwired default must instead reject every reference outright -- silently succeeding would mean an unverified photo attaches to a completion. `noopPhotoOwnershipChecker.Asset` always returns `photo.ErrAssetNotFound`.
- **Added three sentinels beyond the plan's own must_haves list**: `ErrPlaceNameTooLong` (the plan's behavior list requires rejecting an over-bound place name, but only `ErrCaptionTooLong` was named as an export; reusing it would misreport the actual failing field), `ErrInvalidTarget` (TargetKind/TargetValue's required presence-or-absence and bounds needed a sentinel to be testable per the plan's own "target-value bounds are enforced server-side and return their own sentinels" instruction), and `ErrInvalidEventWindow` (EndsOn preceding StartsOn is a genuine data-integrity gap the plan's behavior list didn't explicitly call out but the artifact shape implies).
