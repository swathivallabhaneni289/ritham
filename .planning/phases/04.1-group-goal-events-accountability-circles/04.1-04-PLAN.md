<objective>
Build the server-side photo pipeline whose whole purpose is that a shared or exportable image
cannot carry metadata, no matter what the client sent or claimed.

Purpose: GROUPEVENTS-03 requires unconditional server-side EXIF stripping before any group-visible
or exportable write, plus a required negative test that no code path writes an image to shared
storage without having gone through it. 04.1-RESEARCH.md Pattern 2 supplies the mechanism: Go's
`image.Image` has no field that could carry a metadata segment, so a decode-then-re-encode round
trip through the standard library alone is metadata-blind by construction. This plan makes that
guarantee *structural* rather than procedural, by making the stripped result an opaque type only
the pipeline can produce.

Two gaps this plan closes that the PRD does not anticipate, both found in research:
- **HEIC.** Go's standard `image` package registers JPEG, PNG, and GIF decoders only, and iPhones
  capture HEIC by default. The dangerous failure is not the rejection — it is a later "fix" that
  writes undecoded bytes through. A committed HEIC fixture pins the reject path in this plan, five
  waves before the client transcode that avoids it, so the pipeline is never validated only
  against formats that never arrive (04.1-RESEARCH.md Pitfall 2's own named warning sign).
- **Orientation.** Discarding metadata also discards the orientation tag, which can leave a photo
  sideways. The tag is read before the discard, the rotation is applied to pixels, and the
  rotation itself is hand-rolled rather than taking a second, barely-maintained image dependency
  onto a security-relevant path (04.1-RESEARCH.md's Don't Hand-Roll exception row).

Output: the `internal/photo` package, migration `0002_photos`, and an authenticated upload route.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `POST /v1/photos` | Attacker-controlled image bytes, potentially carrying GPS metadata or crafted to exhaust memory |
| service → object store | Two tiers with deliberately different guarantees; a write to the wrong tier is the leak |
| object store → group members | Presigned URLs are the only read path |
