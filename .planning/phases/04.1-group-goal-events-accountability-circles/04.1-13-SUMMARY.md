## Accomplishments

- `GoalEventsClient.swift` -- six operations (`create`/`list`/`get`/`rsvp`/`withdrawRSVP`/`rsvpState`) mirroring `events_handler.go`'s wire contract character for character. `CreateEventRequest` hand-writes `encode(to:)` so a `nil` target still marshals as an explicit JSON `null` (Go's own request type has no `omitempty` on `targetValue`), keeping the request body at exactly six keys on every call, distinguishable from a `0`-valued target. The completion routes are deliberately not declared here, structurally keeping "no completion figure" true.
- `GoalEventsModel.swift` -- converts wire types to `RithamCore`'s existing `GoalEvent`/`GoalEventTarget` domain types. `upcoming` is a computed property filtering the plain `events` array by an inclusive-whole-UTC-day boundary (matching `internal/events`' own `withinEventWindow` convention) -- a closed event is simply absent from the rendered list, by omission, never marked. The model's only stored properties are `events`, `rsvpCount`, `viewerIsIn`, and `state` -- no roster, no completion figure, asserted by reflection.
- `ActivityTypeIcon.swift` -- the first per-activity-type SF Symbol mapping in this codebase (`04.1-UI-SPEC.md`'s locked table), rendered through the existing `SectionIconBadge`. `symbolName(for:)` is a `nonisolated static` function so Swift Testing's off-main-actor tests can call it directly.
- `CreateGoalEventView.swift` -- name field, activity-type chip picker, a genuinely optional distance/duration target, a starts/ends date window, and the reused `SocialCopy.Certificate.creationTimeNudge` fine-print line beneath the name field (the organizer's own creation-time disclosure that the event name will appear on any exported certificate -- plan 04.1-16 adds the second half of this two-moment check). The primary CTA reads `SocialCopy.GoalEvent.createCTA` ("Start a Group Goal"); the word competing products use for a timed contest appears nowhere in this file.
- `GoalEventRSVPView.swift` -- event name/activity icon, the locked invitee-facing description, the "I'm in" primary CTA, and the headcount line in the app's monospaced-numeral role, the one and only place this number appears. No ring, arc, or radial progress form; no roster or placeholder row for a non-responder.
- `SocialCopy.GoalEvent`/`SocialCopy.RSVP` gained this plan's own field-label and CTA strings, following the existing namespace/no-dash/no-exclamation house style; `SocialCopyTests` (RithamCore) still passes unchanged.
- `OnboardingStep` gained `createGoalEvent`/`goalEventRSVP` (33 -> 35), both terminal in `OnboardingRouter`, matching every other Phase 4.1 social surface's routing precedent.
- `GroupDetailView` is this plan's sole entry point into event creation ("Start a Group Goal" -> `.createGoalEvent`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `domainTarget`'s `return .none` resolved to `nil`, not `GoalEventTarget.none`**
- **Found during:** Task 1, running `GoalEventsUITests` for the first time
- **Issue:** `GoalEventsModel.domainTarget(kind:value:)` returns `GoalEventTarget?`. `GoalEventTarget` (RithamCore) declares its own case literally named `none`. Writing `return .none` inside a function whose return type is `Optional<GoalEventTarget>` is a genuine Swift disambiguation trap: the compiler resolves the bare `.none` to `Optional<GoalEventTarget>.none` (i.e. `nil`) rather than `.some(GoalEventTarget.none)`. Every event -- regardless of its actual target -- silently vanished from `events.compactMap(Self.goalEvent)`, confirmed by adding temporary debug prints before diagnosing the root cause.
- **Fix:** Spelled the case out fully qualified: `return GoalEventTarget.none`. A fully-qualified case reference constructs the non-optional value directly, which then implicitly wraps into `.some(...)` for the function's `Optional` return type -- unambiguous.
- **Files modified:** `RithamApp/Ritham/Social/GoalEvents/GoalEventsModel.swift`
- **Verification:** `aTransportFailureDuringListLoadLeavesEventsUnchangedAndStateFailed`, `upcomingExcludesAClosedEventByOmission`, and `eventEndingTodayIsStillUpcoming` all require at least one event to survive `compactMap` -- all three failed before the fix (every list came back empty) and passed after it. The function's own doc comment now documents this exact trap so a future editor does not reintroduce it.
- **Committed in:** `989ff7e` (Task 1 commit)

**2. [Rule 3 - Blocking] `GoalEventRSVPView.swift` needed a Task-2 stub for `.goalEventRSVP` to be registered**
- **Found during:** Task 2 (adding the `createGoalEvent`/`goalEventRSVP` `OnboardingStep` cases)
- **Issue:** Task 2's own action text adds both new `OnboardingStep` cases in the same commit, but only `CreateGoalEventView` is Task 2's own scope -- without some registered presenter for `.goalEventRSVP`, `PhaseCoverageTests`' `unregisteredSteps`-is-empty gate (an explicit Task 2 acceptance criterion) could not pass.
- **Fix:** Built a minimal stub (matching this codebase's own 02-03/04.1-09/04.1-11 "stub-then-extend" precedent) registered under `.goalEventRSVP`; replaced wholesale in Task 3 with the real implementation.
- **Files modified:** `RithamApp/Ritham/Social/GoalEvents/GoalEventRSVPView.swift` (created in Task 2, rewritten in Task 3)
- **Verification:** Task 2's scoped `GoalEventsUITests`/`PhaseCoverageTests` run passed with the stub in place; Task 3's real implementation still passes both, plus its own new source-level assertions.
- **Committed in:** `daae014` (stub), `706fe7f` (real)
