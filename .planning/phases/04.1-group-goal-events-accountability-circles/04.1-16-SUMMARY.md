# Phase 04.1 Plan 16: Digital Finisher Certificate and Export Summary

**A structurally closed, seven-field `CertificateContent` type composed by `CertificateComposer` (whose only possible photo input is the opaque, server-stripped `StrippedPhotoAsset`) into an auto-generated, auto-revealed certificate that accumulates in a private unranked archive and exports only under a per-subject server consent gate.**

## Accomplishments

- `CertificateContent`/`CertificateComposer`/`CertificateCardView`: a closed seven-field content type with no field able to hold another member's name, photo, status, or time, rendered by a composer whose only photo parameter is the server-backed `StrippedPhotoAsset` — no file URL, raw `Data`, `UIImage`, or `PhotosPickerItem` overload exists anywhere in the call graph.
- Completing a Goal Event now auto-generates a `CertificateRecord` and opens `CertificateRevealView` directly from `CompletionLoggingModel`'s `.logged` transition — no separate send step.
- `CertificateArchiveView` shows every past certificate in accumulation order at reduced scale, with no rank, no comparison, and no count anywhere.
- `CertificateExportView` lets the exporter rename their own copy of the event's display name (a purely local edit, never sent to the server) and gates a photo-bearing export on the server's per-subject export-consent response, with a branded default template that needs no photo and no consent query at all.
- `OnboardingStep` gains `.certificate`/`.certificateArchive` (terminal steps), bringing the step count to 40.
