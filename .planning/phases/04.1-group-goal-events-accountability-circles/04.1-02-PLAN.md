<objective>
Build this phase's pure domain vocabulary and its single-source copy catalog in `RithamCore`,
before any screen or endpoint exists to consume them.

Purpose: two cross-cutting pieces have to land before every UI plan in this phase, per
04.1-RESEARCH.md's Suggested Plan Sequencing — the copy catalog (so no screen re-authors a locked
PRD string) and the visibility scope (so no persistence or wire type is written against a
different ladder shape and later migrated). Both live in `RithamCore`, which the app target and
the test target both depend on, so this plan touches no Xcode project file and runs fully parallel
with the backend foundation.

**Two-rung ladder, third rung reserved.** `docs/group-events.md` §1 describes a three-rung ladder
(Only Me → Household → this specific group). HOUSEHOLD-01 (household grouping itself) is a
separate, still-Pending Phase 4 requirement, so no household tier exists to point a rung at. This
phase therefore ships **two reachable rungs (Only Me → this specific group)** and reserves the
household rung's slot, exactly as Phase 3 did for the identical problem (`MomentumVisibility`
shipped with one case and a reserved `.household`, so Phase 4 could add it with no data
migration — see ROADMAP.md's Phase 3 entry and 04.1-RESEARCH.md Pattern 5). HOUSEHOLD-02's own
requirement wording is "beyond household," and that half is satisfied in full by this phase's
friend-circle mechanism; what stays incomplete until HOUSEHOLD-01 lands is only the ladder's
relative *positioning*, not the friend tier itself. This is stated here, in the plan that creates
the enum, rather than left to be inferred.

Output: seven `RithamCore` source files and two test suites.
</objective>
