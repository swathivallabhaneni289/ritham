# Phase 04.1 Plan 14: Completion Logging, Own-Time Prompt, and Photo/Location Attach Summary

**A five-stage completion-logging model whose single POST fires only after the own-time decision is finalized (internal/events exposes no update route), a structural byte-identical-encoding proof that private distance/duration never reach the group, an on-device HEIC/PNG-to-JPEG transcode pipeline feeding an opaque server-only photo reference, and a completion screen with a genuinely equal-prominence Add-time/Skip pair and two independent photo/location attach chips.**

## Performance

- **Duration:** ~90 min of active tool-use work in this session
- **Tasks:** 3/3
- **Files modified:** 9 created, 9 modified

## Accomplishments

- `CompletionDraft`/`CompletionRequest` structurally separate group-shared fields from
  `PrivateOnly`'s distance/duration -- `outgoingRequest()` reads only the five group-shared
  fields, and a test builds two drafts differing only in `PrivateOnly` and asserts their encoded
  bytes are byte-for-byte identical (with a positive control proving the two drafts' private
  values genuinely differ first, so the assertion isn't vacuous).
- `CompletionLoggingModel`'s single network call is deferred past the binary "done" tap: since
  `internal/events` (04.1-10) exposes exactly one write route and no update route, `logDone()` is
  a local-only stage transition, and the actual `POST` fires only once `skipTime(eventID:)` or
  `addTime(seconds:eventID:)` finalizes the own-time decision. A failed submission leaves
  `stage == .failed` with the draft -- including any already-chosen own time -- fully intact for
  `retry(eventID:)`.
- Location is reached only through 04.1-07's `LocationAttachment.resolveSharedPlaceName`, called
  through a new `LocationFixProviding` seam (its own file) so `CompletionLoggingModel.swift`
  itself names zero CoreLocation types, verified both by a compiler-enforced absence and a direct
  source-scan test. Photo sharing and location sharing are independent opt-ins, asserted
  uncoupled in both directions.
- `PhotoAttachment.encodableJPEG(from data:)` decodes any format `UIImage(data:)` supports
  (HEIC, PNG, already-JPEG) and re-encodes as JPEG using only `UIKit`/`ImageIO`, downscaling first
  so a real capture stays under the server's 9 MiB cap (04.1-04-SUMMARY.md). `StrippedPhotoAsset`
  is constructible only from a `PhotoUploadResponse` -- pinned at compile time, backed by a
  private memberwise initializer, and a source scan confirming no URL/Data/PhotosPickerItem
  initializer exists.
- `CompletionLoggingView`: the binary "done" CTA, the equal-prominence `SecondaryCTAButton` pair
  for Add time/Skip, an inline duration-entry reveal with its own Save/Never-mind actions, two
  independent `ChoiceQuestionView` chip controls for photo/location attach (never a native
  `Toggle`), a visually separate private-only distance/duration section, and the locked
  confirmation headline rendered only once `.logged` is actually reached.

## Decisions Made

See `key-decisions` in frontmatter for the full list. Highlights:

- **Single-POST sequencing** is this plan's most consequential decision: the PRD's copy table
  narrates "done -> confirmation -> own-time prompt" in that order, but `internal/events` has one
  write route and no update route, so a literal read (POST immediately on "done," then a second
  call to add a time) is structurally impossible against the shipped backend. Resolved by making
  the "done" tap a local-only reveal of the own-time prompt, with the real submission deferred to
  whichever of Add-time/Skip finishes last. Verified directly: `logDoneIsLocalOnly` asserts zero
  network requests fire from `logDone()` alone.
- **`LocationFixProviding` in its own file** is the mechanism that lets `CompletionLoggingModel`
  satisfy both "call 04.1-07's `resolveSharedPlaceName`, which takes a raw coordinate" and "name
  zero CoreLocation types" at once -- the coordinate type is spelled in the seam's file, not the
  model's.
- **`StrippedPhotoAsset` built in Task 1**, matching plan 02-03's own documented precedent for
  breaking a forward dependency (`CompletionDraft`'s `photo` field needs the type to exist before
  Task 1 can compile at all).

## Issues Encountered

- `ISO8601DateFormatter` as a `static let` inside `CompletionDraft` (a plain, non-actor-isolated
  struct) tripped Swift 6 strict concurrency's not-`Sendable`-shared-mutable-state check --
  `GoalEventsModel`/`GroupsModel`/`FriendsModel`'s own identical-looking statics are safe only
  because their enclosing class is `@MainActor`. Fixed by making it a computed property (a fresh
  instance per call, negligible cost here) rather than a shared stored instance.
- `PhotosPickerItem` required `import SwiftUI` alongside `import PhotosUI` in `PhotoAttachment.swift`
  to resolve -- `PhotosPickerItem` lives behind a cross-import overlay between the two modules that
  only activates when both are imported in the same file.
- One test-authoring correction, caught before committing: a source-scan test for
  `StrippedPhotoAsset.swift`'s only-allowed-initializers initially false-positived on
  `self.init(assetID: assetID, sharedURL: sharedURL)` (a delegating *call*, not a declaration).
  Fixed by excluding `self.init(` lines from the scan.
