## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan's nonce-flow description was backwards relative to the Go service's actual comparison**
- **Found during:** Task 2, before writing `SocialIdentityModel.swift`
- **Issue:** PLAN.md's action text states "the digest goes into the Apple request, the raw value goes to the server for comparison." `RithamService/internal/identity/apple.go`'s `VerifyIdentityToken` compares `expectedNonce` against the token's `nonce` claim with no hashing step (`nonce != expectedNonce`), confirmed against `apple_test.go`'s literal-value round trip. Sending the raw value to the server as the plan describes would never match Apple's echoed-back digest, silently defeating T-04.1-23's replay protection.
- **Fix:** `nonce()` still returns both `(raw, sha256Hex)` for API/testability parity with the plan's stated signature, but only the digest is used operationally — sent to both `request.nonce` and `AppleSignInRequest.nonce`. Documented inline in `nonce()`'s own doc comment, citing the specific test that proves it.
- **Files modified:** `RithamApp/Ritham/Social/Identity/SocialIdentityModel.swift`, `RithamApp/Ritham/Social/Identity/IdentityClient.swift` (doc comment)
- **Verification:** Logic-level reasoning verified against `RithamService/internal/identity/apple_test.go`'s `TestVerifyIdentityToken_MatchingNonceSucceeds`/`_MismatchedNonceFailsWithNonceSentinel`; no automated test in this plan exercises the live round trip (that requires Task 4's real device/backend, deferred).
- **Committed in:** `82b148b`
