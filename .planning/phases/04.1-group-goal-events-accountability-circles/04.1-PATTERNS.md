## Pattern Assignments

### Backend request/response contracts — `internal/httpapi/contract.go` extensions

**Analog:** `RithamService/internal/httpapi/contract.go` (full file, 34 lines)

**Data-minimization header-comment pattern** (lines 7-23):
```go
// WorkoutPlanRequest is the entire set of values permitted to leave the device (D-07). It has
// exactly three fields: ...
// No stable per-user or per-device identifier is accepted here...
// The field count and JSON tag names below are asserted by reflection in handler_test.go, so
// widening this boundary later fails a test gate rather than passing silently.
type WorkoutPlanRequest struct {
    FrequencyPerWeek   int                     `json:"frequencyPerWeek"`
    ExperienceLevel    plan.ExperienceLevel    `json:"experienceLevel"`
    GuidancePermission plan.GuidancePermission `json:"guidancePermission"`
}
```
**Apply this exact discipline to every new request type this phase adds** — most critically
`CompletionRequest` (must structurally exclude distance/pace/route, per GROUPEVENTS-02) and any
location-attach request (must carry only a place-name string, never coordinates, per
GROUPEVENTS-03). RESEARCH.md's Pattern 1 already gives the target shape for `CompletionRequest`;
this file is the header-comment style and reflection-test convention to copy verbatim.

### Backend HTTP routing/handler — `internal/httpapi/handler.go` extensions

**Analog:** `RithamService/internal/httpapi/handler.go` (full file, 86 lines)

**Route registration pattern** (lines 15-22):
```go
func NewMux() *http.ServeMux {
    mux := http.NewServeMux()
    mux.HandleFunc("POST /v1/workout-plan", handleWorkoutPlan)
    return mux
}
```
Add each new route (`POST /v1/identity/register`, `POST /v1/friends`, `POST /v1/groups`,
`POST /v1/events`, `GET /v1/groups/{id}/feed`, etc.) as its own `mux.HandleFunc` line here — do
not introduce a router framework (RESEARCH.md Standard Stack: extend `net/http`'s `ServeMux`, not
a new dependency).

**Decode-generate-encode three-step handler shape + body-size cap** (lines 11-13, 27-49, 54-64):
```go
const maxRequestBodyBytes = 1 << 16 // 64 KiB
...
func handleWorkoutPlan(w http.ResponseWriter, r *http.Request) {
    req, err := decodeWorkoutPlanRequest(w, r)
    if err != nil {
        writeJSONError(w, http.StatusBadRequest, "invalid request body")
        return
    }
    generated, err := plan.Generate(...)
    if err != nil {
        writeJSONError(w, statusForGenerateError(err), err.Error())
        return
    }
    body, err := json.Marshal(...)
    ...
}

func decodeWorkoutPlanRequest(w http.ResponseWriter, r *http.Request) (WorkoutPlanRequest, error) {
    r.Body = http.MaxBytesReader(w, r.Body, maxRequestBodyBytes)
    decoder := json.NewDecoder(r.Body)
    decoder.DisallowUnknownFields()
    ...
}
```
Every new handler (friend request, group create, event create, completion log, photo upload,
feed query) should follow this same decode→validate/authorize→call-service→encode shape, each
step separately error-checked. `DisallowUnknownFields()` is the existing mechanism enforcing the
data-minimization boundary at decode time — reuse for every new request type, especially
completion-log and location-attach endpoints.

**Error response helper** (lines 81-85): reuse `writeJSONError` verbatim for every new handler
rather than re-implementing error-body encoding.

**New auth-specific pattern needed (no analog exists):** every route this phase adds except
`POST /v1/identity/register` needs bearer-token/session-membership authorization middleware that
does not exist anywhere in this codebase yet (`main.go`'s own header comment: "This endpoint has
no authentication in this first pass"). Build this new, following RESEARCH.md's Pattern 6/
CONTEXT.md's Sign-in-with-Apple-derived session model — there is no existing auth middleware to
extend.

### Backend service package — `internal/identity`, `internal/friends`, `internal/groups`, `internal/events`, `internal/feed`

**Analog:** `RithamService/internal/plan/generate.go` (package boundary/error-sentinel style only
— read via `errors.Is` usage in `handler.go` lines 71-78; the domain logic itself has no analog,
this phase is genuinely new ground per RESEARCH.md's Summary).

**Sentinel-error-per-package pattern to copy** (inferred from `handler.go`'s
`statusForGenerateError`, lines 70-79):
```go
switch {
case errors.Is(err, plan.ErrUnsupportedFrequency),
    errors.Is(err, plan.ErrUnknownExperienceLevel),
    errors.Is(err, plan.ErrUnknownGuidancePermission):
    return http.StatusBadRequest
default:
    return http.StatusInternalServerError
}
```
Each new service package (`identity`, `friends`, `groups`, `events`, `feed`, `photo`) should
export its own named sentinel errors (`friends.ErrAlreadyFriends`, `groups.ErrNotAMember`,
`events.ErrOutsideEventWindow`, etc.), and `httpapi` maps each to an HTTP status the same way —
never a bare `err.Error()` string switch.

### Client network service — per-domain API clients

**Analog:** `RithamApp/Ritham/Recommendations/WorkoutPlanClient.swift` (full file, 172 lines)

**Data-minimization header-comment + Codable mirror pattern** (lines 4-33):
```swift
struct WorkoutPlanRequest: Codable, Equatable {
    let frequencyPerWeek: Int
    let experienceLevel: String
    let guidancePermission: String

    enum CodingKeys: String, CodingKey {
        case frequencyPerWeek
        case experienceLevel
        case guidancePermission
    }
}
```
Every new request struct (`CompletionRequest`, `CreateGoalEventRequest`, `FriendRequestPayload`,
etc.) must mirror its Go counterpart's JSON tags character-for-character, exactly like this file's
comment states, and carry the same "entire set of values permitted to leave the device" framing
for any privacy-relevant payload (completion log, location attach, photo upload).

**Error enum + typed-failure pattern** (lines 67-74):
```swift
enum WorkoutPlanClientError: Error, Equatable {
    case transport
    case httpStatus(Int)
    case decoding
}
```
Reuse this exact three-case shape per new client (or a shared `SocialAPIError` enum used across
all of them) — never a generic `Error` catch-all, since RESEARCH.md's "unreachable service must
read as an error, never an empty/zero result" rule (T-02-38 precedent) applies equally to a group
feed silently rendering as "no posts yet" when the network actually failed.

**baseURL / Debug-vs-Release loopback pattern** (lines 84-98): reuse `defaultBaseURL`'s
`#if DEBUG`/loopback-vs-placeholder-host structure verbatim for every new client, rather than each
client inventing its own base URL constant.

**Async request/response method shape** (lines 109-152): the `guard`-early-return, `URLRequest`
construction, `session.data(for:)` try/catch-to-typed-error, status-code-range check, decode-or-
throw structure is the template for every new client method (`fetchFeed`, `postCompletion`,
`createGroup`, `respondToInvite`, etc.).

### Client persistence — SwiftData local cache records

**Analog:** `RithamApp/Ritham/Persistence/UserProfile.swift` (full file, 76 lines)

**`@Model` shape + nil-safe enum-raw-value accessor pattern** (lines 38-75):
```swift
@Model
public final class UserProfile {
    public var age: Int
    public var dietaryPatternRaw: String?
    ...
    public var dietaryPattern: DietaryPattern? {
        guard let dietaryPatternRaw else { return nil }
        return DietaryPattern(rawValue: dietaryPatternRaw)
    }
}
```
Apply to every new SwiftData cache record (`CachedFriend`, `CachedGroup`, `CachedGoalEvent`,
`CachedFeedPost`): store enum fields as `...Raw: String?`, expose a computed nil-safe accessor —
never force-unwrap a raw value, so a future case rename/removal cannot crash on stale local cache
data (same T-01-64 rationale, doubly important here since this cache is now populated from a
network response, not just user input).
