<objective>
Close the phase: convert every prohibition it depended on into an automated gate, prove both suites
green, and record in the repository what is still unresolved.

Purpose: this phase's correctness is mostly negative — a long list of things that must not exist.
Sixteen plans each asserted their own share of that list locally. This plan adds the gates that
span the whole phase and would catch a regression introduced anywhere in it, following the
per-phase coverage-suite pattern this project has used since Phase 2.

One lesson from Phase 4 shapes how these gates are written. `Phase4CoverageTests` had to add a
separate file-location assertion because a directory walk guarded only by "at least one file was
scanned" stayed green after the code it was meant to cover moved somewhere else. With this phase's
client code spread across nine subdirectories, a bare non-empty check would be exactly that kind of
silently vacuous gate, so each walk here asserts a real floor on what it covered.

Output: two structural suites, an updated deployment record, and the phase's verification
checkpoint.
</objective>

    The gates to write, one named test each:

    Registry completeness — every step case this phase added resolves to its real registered
    presenter type, and the registry reports no unregistered steps after bootstrap.

    Feature-area completeness — the expected nine social subdirectories all exist, asserted by
    name. This is the durable replacement for a bare file-count check and the thing that keeps
    every other walk in this suite honest.

    No ranking or counting field — walk every social source file and fail on identifiers expressing
    a position, a score, a contest board, a winner, a kudos tally, or an ordinal marker, and on any
    formatting of a collection's size into a rendered string. The token list lives in the test file
    itself, so this plan does not restate it.

    No denominator beside a completion count — assert that no file rendering completions also
    references the RSVP step or a headcount property, which is the concrete form the prohibited
    juxtaposition would take.

    Certificate photo restriction — assert the composer's source references the opaque
    server-backed asset type and references no file-path, raw-data, image, or picker photo type.
    This is the source-level companion to the compile-time assertion plan 04.1-16 already carries;
    both exist because this is the phase's highest-severity structural guarantee.

    Geocoder containment — assert exactly one file in the whole client constructs a geocoder, and
    that it is the one that owns the capture, zone-check, geocode, discard sequence.

    No data-bearing ring — assert no social source file constructs a trimmed circular shape or an
    arc in a content area, while leaving the static header ornament untouched.

    Visibility ladder — assert the scope enum has exactly two cases and that a lookup for the
    reserved third rung's raw value returns nil. Write it this way rather than referencing the
    reserved case by name, because the reserved rung is a documentation comment and not a symbol,
    so a test naming it would not compile. This mirrors the existing single-case assertion the
    Momentum visibility suite already uses.

    Platform container and control avoidance — assert no social source file constructs the platform
    list, form, or switch controls, matching this codebase's standing conventions.

    Typography floor — assert no social source file uses a type role below the app's label floor.

    Run `xcodegen generate` and commit the regenerated project file.
