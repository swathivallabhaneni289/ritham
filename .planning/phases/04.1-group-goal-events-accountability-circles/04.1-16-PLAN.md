<objective>
Build the finisher certificate: generated automatically on completion, posted to the group with the
completion, kept in a personal archive, and exportable outside Ritham only under conditions that
make leaking the group structurally impossible.

Purpose: GROUPEVENTS-05 defines a short list of what may appear and a longer list of what may never
appear regardless of any opt-in. This plan satisfies the second list by construction rather than by
filtering: the composer is given a closed content type that has no field for another member's
anything, so there is no value to accidentally render. `docs/group-events.md` §5 names two leak
paths and both are closed here — a group photo containing other people cannot be exported until
each of them grants it, and the free-text event name gets its second disclosure moment as an
editable display name for the exporter, who is usually not the person who wrote it.

The structural catch from 04.1-RESEARCH.md Pattern 4 and Pitfall 5 is the one that most needs
enforcing at the type level: a certificate compositing the client's local original instead of the
server-stripped copy bypasses the whole stripping guarantee even though the pipeline ran correctly.
Plan 04.1-14 already made the only obtainable photo reference a server-backed opaque value; this
plan makes that value the composer's only accepted photo parameter, so the bypass is unreachable
rather than merely discouraged.

Output: the `Social/Certificate/` directory, a locally persisted archive, and two new steps.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| group feed → the public internet | Export is the one path where group content leaves Ritham entirely |
| photo library → composed image | The only place a local original could be reintroduced |
| event name → exported artifact | Free text authored by one person, rendered on another person's export |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

Implements 04.1-RESEARCH.md Pattern 4 and Pitfall 5. |
