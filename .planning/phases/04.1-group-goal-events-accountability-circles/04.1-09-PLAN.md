<objective>
Build the friend-circle surface: a friends list with incoming requests, and an Add Friend screen
offering exactly three closed-loop ways to connect.

Purpose: HOUSEHOLD-02's accountability circle is the friend graph plan 04.1-06 built server-side;
this is the part a person actually uses. GROUPEVENTS-01 constrains the surface tightly — mutual and
request-based only, no public profile search, and no contact scan without an explicit per-side
opt-in. The screen therefore has no search field at all, which is a design requirement rather than
an omission, and the opt-in is a deliberate two-option choice using this codebase's existing chip
control rather than a native switch.

Output: the `Social/Friends/` directory, a shared avatar component, two new steps, and the
dashboard's signed-in social route.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device address book → app | Contact identifiers enter the process when the user opts in |
| app → Ritham backend | Digests and connection intents cross the network |
| invite QR → another person's device | A redeemable secret is displayed on screen |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-51 | Information Disclosure | raw contact identifiers leaving the device | high | mitigate | Only salted SHA-256 digests are submitted, and only while the opt-in is on; turning it off submits the off state with no digests, and the server deletes what it held. Implements GROUPEVENTS-01's both-sides-opt-in requirement. |
| T-04.1-52 | Information Disclosure | a person becoming findable without having opted in | high | mitigate | The client offers no search field and no directory; every connection begins with a request, a two-sided contact match, or an invite the user handed over themselves. |
| T-04.1-53 | Spoofing | an invite QR photographed and reused by a bystander | medium | mitigate | Server-side single-use and window-expiring semantics from plan 04.1-06 mean a captured code is worthless once redeemed or once the window closes; the screen shows the expiry so the user knows the exposure is bounded. |
| T-04.1-54 | Information Disclosure | a network failure rendering as an empty friend list | medium | mitigate | The model's failed state is distinct from loaded-and-empty, asserted by test; the view renders an error rather than an empty state on failure. |
| T-04.1-55 | Information Disclosure | a friend row exposing comparable data | medium | mitigate | Rows carry a name and an avatar only; an acceptance check asserts no numeric value renders in a row. Implements this phase's non-comparative visual rules. |
| T-04.1-56 | Spoofing | a stale session silently failing every friends call | low | mitigate | The unauthenticated error case is distinct and routes the user to sign in rather than showing a generic failure. |
</threat_model>
