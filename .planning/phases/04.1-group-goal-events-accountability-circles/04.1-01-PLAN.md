<objective>
Stand up the persistence foundation every other backend plan in this phase depends on: the
service's first real dependency set (approved package-by-package by a human first), a pgx
connection pool, an embedded versioned migration runner, the first migration (users + sessions),
and a documented local Postgres + MinIO dev stack.

Purpose: `RithamService` today is a zero-persistence, zero-dependency, loopback-bound single
endpoint (`RithamService/go.mod` declares a module path and nothing else). Every subsequent
backend seam in this phase — identity, photo, friends, groups, events, feed — needs a database
handle and a migration story before it can store anything. Landing this once, first, keeps six
later plans from each inventing their own.

Output: `RithamService/internal/store` package, migration `0001_identity`, a dev compose file,
and a `go.mod`/`go.sum` carrying the five approved dependencies this phase uses.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-SC | Tampering | `go get` of six first-ever dependencies | high | mitigate | Task 1 is a blocking human checkpoint verifying every package against its public repository before any install; `go.sum` pins content hashes thereafter. Implements 04.1-RESEARCH.md's Package Legitimacy Audit, including its `[SUS]` verdict on `rwcarlsen/goexif`. |
| T-04.1-01 | Information Disclosure | database credentials in `RITHAM_DATABASE_URL` | medium | mitigate | Credentials live only in the environment and the dev compose file (loopback-bound, dev-only values); no credential is committed in Go source. Implements ASVS V6's "no secrets in code". |
| T-04.1-02 | Tampering | ad-hoc schema edits against a live database | medium | mitigate | Every schema change goes through the embedded, versioned, reversible golang-migrate runner; the store package exposes no force-version or drop helper. |
| T-04.1-03 | Information Disclosure | session bearer tokens stored at rest | high | mitigate | The `sessions` table has no plaintext-token column at all — only `token_sha256 bytea`.
