<objective>
Build the screen where a person logs that they did the thing — and where three separate opt-ins
(their time, a photo, a place) are each offered without being assumed.

Purpose: GROUPEVENTS-02 makes logging binary and puts every embellishment behind its own explicit,
frictionless-to-skip choice. The own-time prompt in particular has a locked shape: the skip action
must be exactly as prominent as the add-time action, which the UI-SPEC translates into two
identically styled secondary buttons side by side rather than a primary action paired with a
de-emphasized link. That asymmetry would be a nudge, and a nudge toward sharing a number is what
the whole design is avoiding.

GROUPEVENTS-03 adds the second rule this screen implements: attaching a photo never implies
attaching a place. They are two switches, always, never bundled.

This screen is also where 04.1-RESEARCH.md Pitfall 2 gets closed on the client side. The server's
strip pipeline decodes only formats the Go standard library knows, and iPhones capture one it does
not, so the client transcodes on-device before upload. Plan 04.1-04 already pinned the server's
reject path against a real capture; this plan makes the reject path stop being hit in normal use.

Output: the `Social/Completion/` directory, the opaque photo-asset type the certificate is later
restricted to, and one new step.
</objective>
