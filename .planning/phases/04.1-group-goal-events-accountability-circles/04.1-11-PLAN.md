<objective>
Build the group surface: create a group, invite friends into it, see who is in it, remove someone
under the group's own policy, and leave with an explicit choice about your past posts.

Purpose: GROUPEVENTS-01's membership mechanics are deliberately unlike the products
`docs/group-events.md` §1 compares against — any member leaves at any time with no ownership
handoff, and the organizer leaving simply continues the group. This plan is where those decisions
become things a person can see and do, and where two specific temptations get resolved against:
a badge marking the organizer, and a silent default for what happens to a leaver's past posts.
The UI-SPEC rules out both by name, and this plan implements those rulings.

This plan also builds `DestructiveCTAButton`, the first consumer of a color token Phase 1 defined
and deliberately left unused because it had no destructive action to attach to.

Output: the `Social/Groups/` directory, a new shared button component, two new steps.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → group routes | The client asserts a group id, a target member, and a leave disposition |
| group membership → what the viewer can see | The UI decides what to offer, the server decides what to allow |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-64 | Elevation of Privilege | the client offering an action the caller is not permitted | medium | mitigate | Removal is offered only when the server-stated policy and the viewer's organizer status permit it, and the server independently rejects an unauthorized removal — the UI check is convenience, the server check is the boundary. Implements Security Domain V4. |
| T-04.1-65 | Information Disclosure | a group becoming browsable or searchable from the client | high | mitigate | No screen in this plan has a text field or a browse affordance for groups; an acceptance check asserts the absence. Implements GROUPEVENTS-01's no-public-tier rule. |
| T-04.1-66 | Information Disclosure | a leaver's past posts handled by a silent default | medium | mitigate | The disposition has no preselected value and the confirm action is unavailable until the user chooses, asserted by test. Implements `docs/group-events.md` §4. |
| T-04.1-67 | Information Disclosure | the organizer's identity carrying visible standing | low | mitigate | No per-row marker of any kind; policy is explained as plain text on the screen instead. An acceptance grep asserts no badge symbol is used. Implements the UI-SPEC's explicit ruling. |
| T-04.1-68 | Information Disclosure | a failed group load rendering as an empty group | medium | mitigate | The model's failed state is distinct from loaded-and-empty and the view renders an error; asserted by test. |
| T-04.1-69 | Repudiation | a member removal with no clear confirmation | low | accept | Removal is confirmed in the UI and is a reversible social action within a twelve-person friend group; no audit log is built, and building one would store more about members than this feature needs. |
</threat_model>
