  <behavior>
    - shift(for:) with a Poor check-in returns the lighter shift.
    - shift(for:) with a Great check-in returns no shift; with an OK check-in returns no shift.
    - shift(for: nil) returns no shift — a skipped check-in is treated identically to a day with no check-in at all, never as an assumed poor state (RECOVERY-01 invariant 4).
    - adjustedSetCount(3, lighter) returns 2; adjustedSetCount(1, lighter) returns 1 (floor); adjustedSetCount(4, none) returns 4; adjustedSetCount never returns a value greater than its input.
    - SleepQuality has exactly three cases with the stable raw values great, ok and poor.
    - SleepCheckIn is Equatable and stores a day-granularity date, a quality and an optional note — and nothing else.
    - A Mirror over a SleepCheckIn instance yields exactly the labels id, day, quality and note — no shield, streak, target or Recovery Week member exists on this type (D-03).
  </behavior>
  <action>
Create `RithamCore/Sources/RithamCore/Momentum/SleepAdjustment.swift`, importing Foundation only.

Declare:
- `public enum SleepQuality: String, CaseIterable, Sendable, Equatable, Codable { case great, ok, poor }`.
- `public struct SleepCheckIn: Sendable, Equatable, Identifiable` — `id: UUID`, `day: Date`
  (day-granularity; the caller normalizes to start-of-day), `quality: SleepQuality`,
  `note: String?`. Nothing else, ever: D-03 forbids collapsing the sleep signal together with the
  Recovery Week flag or the injury freeze, and RECOVERY-01's invariants 6 and 7 require the sleep
  surface to share zero state with Momentum. State that in the type's doc comment.
- `public enum IntensityShift: String, Sendable, Equatable { case unchanged, lighter }` — name the
  no-shift case `unchanged` rather than `none` so call sites read unambiguously against optionals.
- `public enum SleepAdjustment` with:
  - `public static func shift(for checkIn: SleepCheckIn?) -> IntensityShift` — returns `.lighter`
    only for `.poor`; returns `.unchanged` for `.great`, `.ok`, and for `nil`.
  - `public static func adjustedSetCount(_ sets: Int, shift: IntensityShift) -> Int` — returns
    `max(1, sets - 1)` when `.lighter`, otherwise `sets` unchanged.

Document `adjustedSetCount` as an explicit planning decision, in the same spirit as plan 02-08's
documented `experienceLevel()` mapping: reducing prescribed volume by one set (floor of one) is
the only numeric lever the generated plan's shape offers that moves toward
technique-light/lower-force work, it can never increase load, and a future phase with real
graduated prescriptions can refine it without changing this signature. It is deliberately not
invented clinical content and it deliberately does not touch any rep range or added weight.

State the four invariants this file is the enforcement point for, in the header comment: the
qualification bar never changes (nothing here references `CalibrationThreshold`, a duration, a set
minimum or an exercise minimum for *qualification*); a skipped check-in has zero effect; this
rule never consumes a shield; this rule never triggers a Recovery Week. The last two are
structurally true because no ledger type is imported or referenced anywhere in this file.

Write `SleepAdjustmentTests.swift` as `@Suite("SleepAdjustmentTests")` covering every behavior
above, including a test named `skippedCheckInIsIdenticalToNoCheckIn` and one named
`sleepCheckInCarriesNoMomentumState` that uses `Mirror` to assert the exact child-label set.
