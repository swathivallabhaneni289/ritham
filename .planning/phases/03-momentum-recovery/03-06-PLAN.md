03-UI-SPEC.md Component 1: a block grid, never a ring or arc, because the prior UI research named
data forms for Momentum specifically, because the hub screen already renders a circular ornament

arc. Also state that this component must never be placed inside a decorative header region and
must never use the lime accent, and that the adjacency rule the ornament's own header comment
states is satisfied by placement alone.

`ShieldRow(earned:maximum:)` — up to `maximum` shield glyphs left to right, using the filled SF
Symbol shield for earned and the outline variant at `RithamColor.paper` 0.2 opacity for
not-yet-earned, so the earned/unearned distinction carries on both shape and color. Earned glyphs
use `RithamColor.hot`. Render each glyph at roughly 32pt and do not wrap any of them in a
`Button` — these are display-only, deliberately below the interactive tap-target floor because
they are not controls. Below the row, a `RithamType.label` caption with the numerals modifier
reading `MomentumCopy.Shields.shields(earned:)`.

Write into this file's header that no consumption animation of any kind is permitted: when
reconciliation spends a shield, this row simply renders the lower count on next appearance. No
shrink, fade-out, shatter or spent transition. A newly earned shield may use a plain brief
fade-in and nothing more. Any animated loss of a game-like asset reads as punishment, which this
phase's framing rule forbids.

`MilestoneBadgeList(awarded:)` — one row per tier in `MomentumMilestone.tiers`, each showing an SF
Symbol (a rosette for earned, a dashed circle at `RithamColor.paper` 0.2 opacity for not yet
reached), the tier's week count at `RithamType.heading` with the numerals modifier, and the tier's
one-line copy at `RithamType.label` from `MomentumCopy.Milestones.line(forWeekCount:)`. No
celebration animation, no confetti, no full-screen takeover — a newly reached tier simply renders
as earned on next appearance.
