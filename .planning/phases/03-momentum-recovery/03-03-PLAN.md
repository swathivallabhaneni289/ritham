Extend `reconcile` with shield and milestone handling, keeping every write append-only or
monotonic.

On a `met` week: increment `currentStreak`, increment `weeksTowardNextShield`, and when that
counter reaches `MomentumLedger.weeksPerShield`, reset it to zero and set
`shieldCount = min(MomentumLedger.maxShields, shieldCount + 1)`. Then check the new streak value
against `MomentumMilestone.tiers`: if the new value is a tier and `ledger.milestones` contains no
award whose `weekCount` equals it, append a `MilestoneAward` (fresh `UUID`, the tier's week count,
`awardedAt` set to the week's end boundary, not to `now` — the award belongs to the week that
earned it, so a later reconciliation on a different day produces the same value) and grant one
bonus shield, again capped at `maxShields`.

On a `shielded` week: `shieldCount -= 1`, streak unchanged, `weeksTowardNextShield = 0`.

On `paused`, `frozen` and `protectedMiss`: touch none of streak, shield count or accrual counter.

Idempotence is a hard requirement, not an aspiration (03-RESEARCH.md Pitfall 2). The two
mechanisms that deliver it are: the anchor skip from Task 1, and the contains-check before
appending a milestone. Neither may be replaced by recomputing state from the current streak, which
would flip a milestone back to unawarded after a rebuild.

Document, in the file, that a milestone is never retracted even if a retroactive session edit later
changes a past week's derived count — reconciliation only ever asks whether a milestone has already
been awarded, never whether it should currently be true. This is what keeps Momentum compatible
with STRENGTH-05's shipped retroactive edit/merge/split feature.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted session records → derived Momentum state | Session data is user-editable after the fact (STRENGTH-05's retroactive edit/merge/split), so derived state must be tolerant of a past week's count changing |
| repeated reconciliation calls → ledger | Every app foreground and every Momentum screen appearance re-enters this function; a non-idempotent fold corrupts the user's motivational state |
