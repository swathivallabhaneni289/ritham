## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → Go workout-plan service | Phase 2's D-07 three-field data-minimization boundary; adding a field is a privacy-review decision, not an implementation detail |
| sleep signal → Momentum ledger | RECOVERY-01's invariants forbid the adjustment from consuming a shield or triggering a Recovery Week |
| sleep signal → app-wide visual state | Invariant 3 requires a skipped check-in to be indistinguishable from a day the prompt never appeared |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-13 | Information Disclosure | `WorkoutPlanRequest` boundary | high | mitigate | The adjustment is applied entirely after the client returns; the request type and the client file are untouched, pinned by `theWorkoutPlanRequestStillCarriesExactlyThreeFields` inspecting the serialized key set and by a no-diff gate on the client file |
| T-3-08 | Elevation of Privilege | sleep signal to guardrail state | high | mitigate | Pinned by `theAdjustmentNeverConsumesAShield` and `theAdjustmentNeverTriggersARecoveryWeek`, both exercised with a Poor check-in stored |
| T-3-12 | Information Disclosure | skipped-check-in visibility | medium | mitigate | The hub CTA label is a constant with no dependency on stored state, and `skippingTheCheckInHasZeroEffect` asserts an identical plan and an identical summary against a Great-check-in day |
| T-3-14 | Tampering | prescribed volume adjustment | medium | mitigate | `theLighterAdjustmentNeverIncreasesPrescribedVolume` bounds the single numeric lever in both directions; the rep range, focus and guidance note are never modified, so no unreviewed prescription content is generated |
