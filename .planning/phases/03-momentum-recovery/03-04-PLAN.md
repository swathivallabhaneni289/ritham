<objective>
Persist the Momentum ledger. Add the SwiftData records for Momentum state, milestone awards,
comeback windows, Recovery Week periods and injury freeze periods; register them in the app's
single model container; and extend the `HealthDataStore` facade with the load/save methods plan
03-05's reconciliation-on-read driver calls.

Purpose: 03-RESEARCH.md's Data Model Shape prescribes exactly two proven persistence shapes for
this phase — a single upserted row for scalar state, and append-only date-addressable rows for
event history. This plan implements both against the existing file's patterns and invents no
third shape.
Output: two new record files, an extended container and facade, and a store test suite nested
under a new serialized parent.
</objective>

  `compactMap` shape.
- `public func appendRecoveryWeekPeriod(_ period: RecoveryWeekPeriod) throws` — inserts a row only
  when no stored row already has the same `weekStart`, so flagging the same week twice is a no-op
  rather than a duplicate. Per D-12 the flag pauses that entire week retroactively for

  no-op.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings input → persisted weekly target | A value written through any path other than the picker must not reach the stored preference (ASVS V5) |
| reconciliation output → persisted ledger | The write path can defeat the fold's append-only guarantee if it deletes rows the fold merely omitted |
| self-reported injury/Recovery-Week data → device store | New health-adjacent self-report data at rest; already inside the existing container's file-protection class, adding no new network egress |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Tampering | `HealthDataStore.saveMomentumTarget` | medium | mitigate | Guards against `supportedMomentumTargets` and throws `unsupportedMomentumTarget`, persisting nothing — never clamping — exactly mirroring the shipped `saveWeeklyFrequency`; pinned by a test asserting the previously stored value survives the throw |
| T-3-04 | Tampering | `HealthDataStore.saveMomentumLedger` | high | mitigate | Insert-if-absent and update-claim-fields-in-place only; no delete call in the Momentum section, pinned by a delete-count acceptance gate and by a test that a stored milestone survives a save whose ledger omits it |
| T-3-08 | Elevation of Privilege | guardrail record independence | medium | mitigate | No SwiftData relationship exists between the Recovery Week, injury freeze, sleep and Momentum state records, and no facade method reads one machine and writes another — D-03's no-auto-transition rule made structural rather than conventional |
