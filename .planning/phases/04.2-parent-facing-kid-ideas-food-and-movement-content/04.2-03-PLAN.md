<objective>
Build KIDCONTENT-02's persistence: a `ChildEntryRecord` SwiftData model carrying an identifier, an
optional nickname, and a creation timestamp and nothing else (D-07, and the ordinal-slots-with-an-
optional-nickname default CONTEXT.md's Claude's Discretion section sets), registered in the app's
one file-protected container, with per-entry add, rename, and delete accessors on `HealthDataStore`.

Purpose: this is the phase's one piece of genuine design judgment. Because D-07 lets a parent record
MORE than one child and edit each independently, the correct precedent is `PrivacyZoneRecord`'s
per-entry-UUID CRUD, not `FoodAllergenRecord`'s delete-every-row-then-reinsert-the-whole-set shape.
The latter would silently destroy every other child entry on any single edit. D-06's single preteen
band means no age field is needed at all, and D-09's read-only content rule means nothing in this
plan may persist per-idea state.

Output: `ChildEntryRecord.swift`, a `MARK: - Child entries` section on `HealthDataStore`, one new
`HealthDataStoreError` case, and `ChildEntryTests.swift`.
</objective>

  <action>
    Add a new `// MARK: - Child entries` section to `HealthDataStore`, placed immediately after the
    `// MARK: - Certificates` section and before `// MARK: - Private`, holding five methods plus
    two private helpers.

    `public func loadChildEntries() throws -> [ChildEntryRecord]` -- fetches
    `FetchDescriptor<ChildEntryRecord>` with `sortBy: [SortDescriptor(\.createdAt, order:
    .forward)]`. Sorting here, not at the call site, is what makes the view layer's ordinal labels
    ("Child 1", "Child 2") stable across relaunches. Returns records directly, following
    `loadCertificates()`'s precedent -- this phase introduces no separate domain value type for a
    child entry, because the record carries no computed or decoded field that would need one.

    `public func saveChildEntry(id: UUID, nickname: String?, createdAt: Date) throws` -- if a record
    with that identifier already exists, delete it; then insert a fresh `ChildEntryRecord` built
    from the three parameters with the nickname run through `normalizedNickname`; then
    `context.save()`. This is `savePrivacyZone`'s delete-then-reinsert discipline, which guarantees
    a re-save can never leave a stale field behind. It takes value parameters rather than a
    `ChildEntryRecord` instance (a documented deviation from 04.2-RESEARCH.md Pattern 2's literal
    signature) so a caller never has to construct a `@Model` object outside a `ModelContext`; the
    method name and its per-identifier semantics are unchanged from the research recommendation.

    `public func addChildEntry(nickname: String? = nil) throws -> UUID` -- mints a fresh `UUID` and
    a `Date()`, calls `saveChildEntry`, and returns the new identifier. This is the call shape the
    view layer uses, mirroring `PrivacyZoneStore.add`'s "caller supplies values, store owns
    identity" split.

    `public func renameChildEntry(id: UUID, to nickname: String?) throws` -- fetches by identifier,
    throws `HealthDataStoreError.childEntryNotFound` when nothing matches, otherwise assigns the
    normalized nickname and saves. Never touches `createdAt`, which anchors the entry's ordinal
    position. Mirrors `renamePrivacyZone` exactly.

    `public func deleteChildEntry(id: UUID) throws` -- fetches by identifier, throws
    `childEntryNotFound` when nothing matches, otherwise deletes that one record and saves.
    "Not found is an error, not a silent no-op", matching `deletePrivacyZone` and
    `deleteCardioSession`.

    `private func fetchChildEntryRecord(id: UUID) throws -> ChildEntryRecord?` -- fetches all
    records and returns the first whose `id` matches, exactly as `fetchPrivacyZoneRecord` does.

    `private static func normalizedNickname(_ raw: String?) -> String?` -- trims whitespace and
    newlines; returns `nil` when the input is `nil` or trims to empty, otherwise the trimmed
    string. This is what keeps an empty text field from persisting an empty string that would then
    render as a blank row instead of falling back to its ordinal label. Its doc comment must say
    so.

    Add `case childEntryNotFound` to `HealthDataStoreError` with a doc comment in the same style as
    the existing `zoneNotFound` case, naming `renameChildEntry` and `deleteChildEntry` as its
    throwers.

    Add a doc comment above the section recording that these accessors are deliberately isolated
    from gate resolution: nothing here is read by `GateResolution`, `TagDerivation`, or
    `saveScreeningResult`, and no child entry is ever sent anywhere. That is the same isolation the
    Privacy Zones and food-allergen sections already establish, and it is what keeps this
    parent-provided preference from touching the app's own health-screening path.
  </action>
